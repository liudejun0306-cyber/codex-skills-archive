# 中国合同起草、审查与修改

## 一、核心定位

合同技能的任务是把客户的交易目的和经营安排转化为明确、可履行、可留证、可追责的合同条款，不是机械套模板，也不是只列风险提示。

主流程：

`确认客户立场和任务 → 理解实际交易和履行流程 → 确定核心交易条件 → 选择通用起草、个性化起草、局部修改、完善或重构 → 建立权利义务和违约救济 → 全文交易衔接检查 → 表达审查 → 格式化交付`

## 二、任务分流

- 通用起草：客户没有特殊要求，但仍应结合行业、经营内容和实际履行形成可用标准版本；
- 个性化起草：把客户特别要求写入对应的付款、履行、验收、运营、分配、限制、解除和违约条款；
- 无特别交代的审查：主动检查过于简单、遗漏、矛盾、错误、失衡、责任空缺和执行障碍；
- 有特别交代的审查修改：落实客户要求，同时检查其对其他条款的连带影响；
- 局部修改：保留原结构、编号、表格和格式，只改目标条款及必然关联条款；
- 整体重构：原合同法律关系、交易流程或核心条款无法通过局部修改修复时，提取有效信息后重新组织。

## 三、商事合同以交易条款为核心

优先写清：

1. 谁是实际责任主体，谁有签约和履行权限；
2. 标的、数量、范围、成果和排除事项；
3. 价格、税费、发票、付款节点和付款条件；
4. 交付、风险转移、验收、异议、整改和复验；
5. 双方配合事项、资料、场地、人员和手续；
6. 变更、追加、延期和价格调整程序；
7. 解除、退出、交接、结算和存量事项；
8. 与每项重要义务相对应的违约责任；
9. 通知送达、争议解决、生效和附件优先顺序。

不得先堆保密、不可抗力和争议解决，却只用几句概括真正的交易内容。

## 四、表达硬规则

- 合同标题和条款名称使用规范、习惯表达，如“合同标的”“价款及支付”“交付与验收”“违约责任”“合同解除”“争议解决”；
- 不随意创造“交易资金运行机制”“责任抓手”“业务闭环”等词语；
- 条款写明谁、做什么、何时、标准、程序、证明方式和违反后果；
- 避免“及时、尽快、相关损失、妥善处理”等无明确标准的表述；
- 不使用意思不明、翻译腔或不符合大陆合同习惯的句式；
- 修改后自动调用中文表达技能，检查具体性、歧义、逻辑、标点和术语统一。

## 五、修改和全文复核

1. 用户最新版本是唯一底稿；
2. 用户指出哪里有问题，优先修改哪里；
3. 修改付款、验收、期限、解除或责任时，同步检查所有关联条款；
4. 修改后必须通读全文，检查重复、冲突、定义漂移、金额日期不一致、编号和交叉引用错误、责任重复或责任空缺；
5. 全文复核不等于全文重写；未受影响的有效内容和原格式应保留；
6. 重构前先列出原合同中应保留的主体、标的、金额、期限、特别要求和已确认安排。

## 六、自动联动

- 完整合同自动适用 `$chinese-writing-style`；
- 用户要求输出、生成、整理成、形成或制作合同、协议、Word、DOCX、PDF时，自动适用 `$chinese-document-output-style`；
- 修改源文件时优先原位编辑并保留原格式；
- 普通单份合同不进入案件工作台；合同属于具体诉讼、长期顾问项目或用户明确要求时，才调用案件同步技能。
